# RND slurm submission convention — generic part in the SHARED submit-cpu-sweep skill (2026-07-11); RND specifics kept here

The full submission convention lives in the SHARED skill
`/p/rlprojects/.claude/skills/submit-cpu-sweep/SKILL.md` (moved 2026-07-11; readable by every
rlprojects member — it applies to large CPU sweeps in every project on this cluster, not only
RND). It covers: reservation discovery, open-partition buckets, the curated gpu allowlist,
job shapes (`--ntasks-per-core=2`, task count <= physical cores, sizing against CPUEfctv),
`srun --wait=0`, job names, batched submission, submission order (open partitions first, reserved
nodes last), the 16-CPU user headroom, and capacity planning over the per-user pools. The
queue/id/logging convention is in the same skill. Cluster facts:
`/p/rlprojects/.claude/rules/cluster-slurm.md`. Collaborators adding workers to a live run follow
that run's `for_collaborator/README.md` (generated by
`/p/rlprojects/.claude/skills/collab-handbook/SKILL.md`).

Repeated here because everyone working in this repo must know it — the cancellation safety rule:
- **Never blanket-cancel** (`scancel -u <user>`, `scancel -t PD`/`-t R`, `scancel -n <name>`). Only
  `scancel` the job ids recorded at submit time in
  `train_runs/<run>/slurm/submitted_jobids_<sweep_id>.txt`.

## RND instantiation (project facts)

- Config source: a **local file work queue** in the run folder, not a W&B sweep.
  `slurm/launch_queue.sh` builds the queue and submits the jobs; the workers
  (`slurm/worker_*.slurm` running `slurm/worker.py`) atomically claim configs from
  `queue/<sweep_id>/pending/` and run `train.py` with `use_wandb=False`.
- The launch and worker scripts call the env's python by FULL PATH — no conda activation is
  needed in the launching shell. The canonical project env is the SHARED
  `/p/rlprojects/RND/.venvs/exploration/bin/python` (see `.venvs/ENVS.md`; runs launched up to
  3.2.3 used the now-retired `/u/sl5nw/.conda/envs/exploration`, kept for reproducing them).
- Per-run slurm scripts live in `train_runs/<run>/slurm/`; job logs in `train_runs/<run>/logs/`;
  per-run JSON records under `train_runs/<run>/data/<sweep_id>/local/` (record format:
  `run-id-and-logging.md` next to this file).
- This work-queue convention supersedes the old `wandb agent` fan-out (the former
  `.claude/rules/slurm.md`, deleted 2026-07-08).
